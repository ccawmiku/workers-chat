# v1.2.0：请求前缀与双窗口对比

基于 main `9dd36d4`（PR #5）。参考用户提供的 CACHE_OPTIMIZATION_RECOMMENDATIONS.md 后，按实际消息构建器验证；不采用会改变 UA 对调、丢弃历史或累积旧全文的方案。优化目标是可复用的请求前缀，不是界面显示的百分比。

## 请求编排

- 主窗口保留完整当前路线、主 system、真实正文和已有辅助轨迹。新字数工具明确只约束紧邻的一轮，保存 `stable:true`，后续在原位置原样恢复，包括工具 ID；下一轮不再删除它而打断前缀。旧无作用域记录仍清理字数工具，避免追溯改变旧约束含义。
- 补充提问/写前分析：同模型、同 system 且都开启时，先共享 U/S 与最近原文，再放各自固定任务和参考。没有可共享的前置插件时，自己的固定任务/Schema/示例提前，历史参考在对应 U 后按条插入，最新要求放最后。
- 追问/重写：同模型、同自定义规则与 U0 时共享原来的 UA 对调前缀；没有兼容伙伴时，将固定输出契约移到固定 system，尾部只放任务输入。原 U 完整、A 优先有效摘要/缺失前300字符、U0 非空和候选数量不变。
- 摘要历史改为每条独立 JSON 消息，追加新记录不重写旧消息包裹。100–150字目标、历史 U 首尾500、上轮 A 范例首尾2500、本轮完整 UA、格式验证与确认流程保持。
- 标题模板在前，选中的真实聊天片段在末条 JSON，通过稳定 reference 对应模板占位符。自定义模板、START/END 范围及标题验证保留。

晚到/替换摘要、编辑删除历史、重置参考、修改规则或模型仍会改变相关前缀；不能为缓存保留过期事实。不添加预热、padding、未知缓存参数、统计轮询或失败自动重发。原缓存显示和计算保持。

## 双窗口

右栏“模型对比”按聊天持久保存，默认关闭。支持独立模型、温度、Top P、Top K、思考强度；空模型跟随主窗口，空采样参数沿用主聊天及所选模型的默认链。配置用于下一次生成。

每次主回复至多创建一个普通 fork，并关闭 fork 自身的对比开关。新请求只从当时主窗口当前 U 出发，不接续之前对比回答。重新生成/继续回答也创建独立记录。右栏概述列出真实分支标题，可在正常聊天窗口打开。

- 沿用模式：主窗口历史及本轮实际工具结果，不额外运行前置插件。
- 纯净模式：主 system + 当前主路线真实 UA + 最新 U；移除历史工具轨迹与本轮插件/本地字数工具。U 本身文字保持。

两窗口独立流式输出/停止，对比模型失效不阻断主回复。设备直连沿用现有内存凭证和防重复机制，保存失败可单独重试保存。对比初始回答不自动启动摘要/追问；打开该 fork 后后续正常聊天不受影响。关闭开关停止当前对比、隐藏额外窗口，已保存 fork 保留。桌面并排，窄屏横向滑动，最多一个额外面板。

开启对比多一次主模型请求及普通 fork 存储，是功能本身的成本。长聊天仍完整快照存储，未扩展到数据库架构重做。

## 验证口径

`node scripts/cache-audit.mjs --baseline origin/main` 只比较消息/文本前缀，不调用模型，不能当成实际 cached_tokens 或计费降幅。真实命中受上游路由、模型、阈值和有效期影响，以接口返回为准。发布证据见 [PRODUCTION.md](PRODUCTION.md)。
