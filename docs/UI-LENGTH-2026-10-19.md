## 字数要求

按聊天保存的本地辅助插件，入口在插件菜单和右栏。它不调用模型、不显示上下文卡。写前分析确认/跳过之后、正式主回复之前，使用每轮默认自由文本；默认空白时复用下方输入框询问，以主题色提示，临时内容独立于主草稿。可填“3000字”“多写点”或直接提交未提供，不做纯数字校验。

本轮其他前置工具之后追加一对 assistant.tool_calls/tool，只有三个顶层字段：上一轮要求、上一轮实际输出、本轮要求。上一轮取本分支最近主回复；Unicode正文字符数包含标点空白、不含思考，上游输出Token扣除可识别思考，没有该计数时不伪装已知。手工编辑后的字符数重新计算，上游Token仍属于原始生成请求。第一次/缺要求明确未提供。模型只能据此参考，不保证精确长度。

主回复记录当次要求，重试/继续沿用当次信息；历史辅助轨迹里的字数工具下次不还原，其他工具轨迹保留，故不累计。外部导入/旧记录无此元数据时上一轮要求未知；普通导出仍排除辅助轨迹。

## D1 写入与限制

相同草稿 PUT 现在用一次 JOIN 同时核验聊天和已有草稿分块，完全相同就跳过整个写批次。仍是一次 SQL 往返，但读取草稿内容比原来的存在性检查多读字节；真实变更/清空照常原子写入，独立空草稿仍覆盖旧快照中的草稿，不因“值为空”误跳过迁移。

本地 Miniflare D1 元数据：已有一块短草稿，旧重复写路径 `rows_written=4`，新重复保存 `0`；新建首次写4。测试另覆盖空草稿、多分块Unicode、真实新文本和不存在的聊天。这是本地行计数，不是线上全账号账单或整体降幅。长聊天正文真实改变仍保存完整版本快照；本次没有扩大为增量存储重构。

字数插件没有独立模型请求；仅开启字数插件、已有固定默认文本且没有其他前置插件时，直接随主请求注入，不创建额外等待流程/快照。需要本轮交互时才保存等待状态；主回复要求仍随消息保存，不能把本地计算等同零 D1 成本。
