# 手机版网页构造测试

2026-10-16，基线 `840f5a4`。用户确认目标是手机版网页；SPEC 中的 ChatGPT iOS 只是消息菜单交互参考，不要求开发原生 iPhone App。

## 测试数据与环境

- 自己构造两个聊天，保留相同的消息节点 ID，以检查编辑状态是否跨聊天串用。
- 长消息含 80 段文字、长代码行和表格；独立无密钥服务商使用 `fixture.invalid` 和缓存的模型列表，不请求外部模型。
- Playwright 1.64.1，Chromium 与 WebKit 27.2；两者都设置 `isMobile: true`、`hasTouch: true`。WebKit 是 Linux 下的 Safari 引擎测试，不是实体 iPhone Safari。
- 视口宽度 320、390、760、844；高度含 360、390、740、844。矮视口模拟可用空间缩小时的布局，不声称已打开真实系统键盘。
- 使用真实浏览器触摸点击，Chromium 另通过 CDP 发送触摸滑动与长按；两种引擎都执行确定性的 pointer 长按/移动取消序列。
- 全局拦截意外 `/send`，要求发送次数为 0，避免回车回归触发真实模型请求。

环境缺少系统安装权限，本次将 Debian 官方依赖包解压到仓库外，再放入 WebKit 的本地浏览器缓存。Playwright 的 dlopen 检查只读系统 ldconfig 缓存，因此本次进程设置 `PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=1`；实际浏览器启动和全部用例均成功。该变量不写入项目配置；普通机器按 [DEPLOYMENT.md](DEPLOYMENT.md) 安装依赖即可。

## 复现与修复

| 问题 | 修复及验证 |
| --- | --- |
| 手机横屏宽度大于 760 后，Enter 被当成发送，模型搜索自动聚焦 | 除布局宽度外检查 hover/fine pointer；两种引擎横屏均保留换行，搜索点击后才聚焦，未提交生成 |
| 正好 760px 时打开聊天不关闭导航遮罩 | JS 与 CSS 使用相同边界，打开后遮罩移除 |
| 两个聊天有同名节点时，旧聊天未保存的编辑框出现在新聊天 | 打开聊天重置编辑和菜单，并取消旧长按计时器；新聊天显示自身正文 |
| 矮屏的消息菜单顶部移出屏幕 | 菜单高度受动态视口约束，可独立滚动；390×360 内矩形完整可见 |
| 侧栏宽度取决于最近一次 React 渲染，旋转后可能沿用不合适的宽度 | 用 CSS 自定义属性保存桌面宽度，由媒体规则切换；无需状态更新，844px 为记忆的 190px，760px 为手机 280px |

## 结果

- `npm run test:browser`：7 项通过，包含原有 3 项和新增 2 场景 × 2 引擎。
- `npm test`：原有 30 项全部通过；类型检查与构建通过。
- 验证窄屏布局、长代码局部滚动、模型搜索焦点、手机回车、横竖屏、参数面板、消息菜单、长按取消、触摸滑动、跨聊天编辑、草稿保存/刷新与页面无脚本异常。
- 截图：[Chromium 手机](screenshots/mobile-touch-chromium.png)、[WebKit 手机](screenshots/mobile-touch-webkit-mobile.png)。仅含构造数据。

实体手机的系统键盘、浏览器地址栏、文字选择与辅助功能仍需后续设备覆盖；这不是额外的原生 App 功能，也不影响已完成的本地浏览器测试结论。其他产品实现限制继续以 [PROGRESS.md](PROGRESS.md) 为准。本轮没有真实上游生成或生产部署。
