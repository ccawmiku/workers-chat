## 一、产品目标和边界

做一个网页和后端运行于 Cloudflare Workers 的单用户聊天应用，调用用户自己的 OpenAI 兼容 API。聊天行为借鉴最新版 OpenWebUI，视觉借鉴用户提供的 Codex 截图。

Cloudflare 套餐限定：只允许免费套餐，不把付费套餐、收费附加功能或升级作为已授权备选。模型 API 的调用由用户提供的连接承担，不与 Cloudflare 免费套餐混淆。

已确认不提供：

- RAG、知识库、文档检索、图片生成。
- 多用户、注册、组织、权限管理。
- 新消息中的图片/文件附件输入、语音输入和输出。
- 代码语法高亮、数学公式解析；普通等宽代码块和复制仍保留。
- 临时聊天（原 A5 已取消）。
- 消息排队（原 C 相关排队设计、19B、57—62 已取消）。
- Responses API，当前协议范围为 Chat Completions。
- 手动添加模型、模型别名和模型收藏。
- 自动总结/压缩旧消息。
- 聊天标题和正文搜索、时间分组。
- PWA/添加到主屏幕专项功能、回复完成系统通知、跨设备即时消息同步。
- 输入框附件加号、麦克风、语音按钮、Codex 权限选择。
- 大量上游高级参数；不主动设置最大输出长度。

## 三、登录、存储与备份

- 一个用户，一个访问密码，无注册。
- 保持登录，直到主动退出、设备会话被撤销或修改密码；不采用固定 30 天到期（45B）。
- 可修改密码，并使其他设备登录失效。
- 提供登录设备列表，可退出指定设备或退出全部设备。
- 首次密码在部署时设置，无公开注册/认领入口（127A）。增加可预先保存的离线恢复码；通过恢复码重设密码后注销全部会话（128B）。恢复码按凭证处理，不存明文校验值、不写日志或 Git。
- 不增加额外快速锁屏功能（110A）。
- 聊天记录云端保存，手机/电脑登录后读取同一份数据；不做普遍实时同步，但打开或重新加载聊天应读取服务端当前内容。
- 每个聊天的草稿保存到云端（18B）；同一草稿多设备修改时最后一次保存覆盖前值（63B）。
- 本应用设置可导出/导入：系统模板、生成参数、服务商地址等；密钥有独立勾选项，默认不导出（44A）。
- OpenWebUI 兼容聊天 JSON 和本应用完整设置备份应明确区分，不能声称 OpenWebUI 的聊天导出本来就含登录密码或全部应用配置。
- 全量聊天导出包含普通、归档聊天；回收站有独立导出选项（65A）。
- 导入本应用设置备份时可选择合并或替换（125A）；不改变聊天 JSON 每次新增会话的规则。
- 选择包含 API Key 的设置备份为普通 JSON，不额外强制密码加密，下载前明确标注包含密钥（109B）。默认仍不勾选密钥，不自动上传备份。

### 3.1 已确认的连接安全底线

- 用户明确要求全部连接安全，至少聊天正文不能在网络链路上以明文传输。
- 正式环境浏览器 ↔ 本应用后端使用 HTTPS；如采用 WebSocket 则使用 WSS；本应用后端 ↔ 模型 API 使用 HTTPS。
- 不允许本项目建立的公网转发链路降级到明文 HTTP，不关闭证书校验，不在携带密钥时跟随未经校验的跨域/降级重定向。
- localhost 测试接口与正式连接分开，不把本地 HTTP 作为生产连接模板。
- 上游 API Key 由服务端安全保存，避免放入公开前端构建、URL 查询参数、日志、源码或仓库。客户端提交配置也必须使用加密链路。设置中允许在再次验证登录密码后查看已保存的 API Key（107B），不得在常规列表或聊天接口自动返回原值。
- 登录采用服务端密码散列及安全会话 Cookie；聊天/设置接口需要认证，并防止跨站请求和明显的暴力尝试。这些属于落实单用户登录的工程要求，不是新增多用户或权限模块。
- 日志和诊断默认不记录聊天正文、系统提示词、密钥或完整认证头；请求预览/导出中与密钥有关的信息按用户选择和明确用途处理。
- 这里要求的是传输加密；Worker 与模型服务处理请求时仍会读取内容，不声称实现“只有用户终端能解密”的端到端加密。
- 用户选择不额外做聊天正文的应用层加密（108B）；这不放宽传输加密，也不授权明文保存上游密钥。不能把所选方案宣传为终端端到端加密。

## 四、服务商与模型

- 可配置多个服务商：名称、Base URL、API Key；在设置页面集中管理。
- 自动获取模型列表；保存服务商时获取一次，之后手动刷新。
- 不支持手动添加模型。不支持任意模型别名/收藏；用户本轮新增的可选提供商前缀单独保留，不等同于任意改名功能。
- 增加模型启用/关闭开关；关闭只从发送框选择列表隐藏，已选聊天、历史和默认模型引用仍可用（102A）。此项覆盖旧 35B“全部显示”。
- 首次获取和后续刷新出现的新模型默认关闭，由用户开启（103A）；支持全部开启、全部关闭、仅开启搜索结果（104A）。
- 发送框模型选择菜单增加搜索；原始模型名、前缀、提供商名称均可匹配（105A）。电脑打开自动聚焦，手机点搜索框才唤起键盘（106A）。模型仍平铺显示并标注服务商（33B），视觉借鉴 Codex。
- 支持每个提供商填写一次可选前缀，应用于该提供商全部模型，如 OR/（100A）。前缀仅用于界面区分，上游 model 仍发送原始 ID（101A）；内部保留提供商身份与原始 model ID，不能仅靠名称合并同名模型。
- 可测试地址、密钥和指定模型连通性。
- 可设置默认聊天模型。
- 当前聊天可切换模型，发送当前选中分支的已有文字上下文。
- 导入/历史模型不存在，或与当前列表无法匹配，自动使用默认模型；原消息模型元数据保留用于显示和兼容导出。
- 若默认模型本身也不存在或不可用，不能发送，给出提示，不自动改用列表首个模型（73）。
- 每个模型有可编辑的上下文容量，初值一律 1,048,576 Token。此数值是应用预算配置，不扩张上游实际限制。
- 生成参数支持全局默认 → 模型默认 → 当前聊天手动覆盖（30A）；系统提示词另按“只属于当前聊天”处理。
- 切换模型保留当前聊天手动设置的参数，其余采用新模型默认值（52A）。
- 当前聊天生成期间允许切换模型，只影响下一次发送，不改变已开始的请求（74A）。

### 4.1 思考强度

在输入框内选择，不在右侧参数面板重复显示。

| 中文标签 | 请求值/行为 |
| --- | --- |
| 跟随接口 | 省略推理强度字段，不发送空字符串或 null |
| 无 | 发送 none |
| 低 | 发送 low |
| 中 | 发送 medium |
| 高 | 发送 high |
| 最高 | 发送 max；新聊天默认选中 |

“跟随接口”是对用户所说“缺失/不填”的命名，需与显式发送 none 的“无”分开。不加入 xhigh、minimal 等未选档位。不设置单独的模型默认思考强度，新聊天统一默认最高 max（72B）；数值生成参数的模型级默认仍按 30A 保留。

上游不支持参数时显示具体错误并保留设置，用户自行调整（49A）；不静默移除参数、降低强度或自动切换协议。

### 4.2 右侧当前聊天设置

已确认需要：

- 系统提示词/模板选择入口（75A）。
- 流式开关。
- 温度 Temperature。
- Top P。
- Top K。
- 停止后的半截回复是否参与后续上下文。
- 重新选择系统模板时采用替换或追加，由右侧切换项选择，默认替换（78、130A）。
- 手动重新生成标题时使用当前分支还是首轮问答，由右侧切换项选择，默认当前分支（80、131A）。
- 上下文轮数限制能力仍保留；与右侧四个主要生成参数如何布局可在实现时简洁整合，不擅自删除 E3。

流式默认开启。温度/Top P/Top K 初始显示“默认”，未设置时不发该参数，交给上游处理（50A）。数值控件采用滑块＋数字输入，并可恢复默认（51A）。不提供不必要的其他高级参数；不主动设置最大输出 Token 上限（29）。

## 五、聊天、生成与分支

### 5.1 生成

- 多轮聊天，支持流式和非流式。
- 可停止、重新生成、失败后手动重试。
- 同一个聊天未生成完不能再发送；可继续编辑输入草稿。不维护排队列表，不在回答完成后自动发送草稿。
- 不同聊天可分别生成（原 C9 保留）；“取消排队”不等于取消跨会话并行。
- 普通聊天关闭网页后当前已开始的回答继续生成并保存，回来可查看。具体后台生命周期方案在实现阶段选型，不以早期“不需要 Durable Objects”的初步判断限制实现。
- “继续回答”接在当前 AI 回答末尾；保留续写前版本，新版本为原回答加续写内容，页面显示为同一回答的另一个版本（114A）。
- 停止后保留已收到的部分；默认参与后续上下文，右侧当前聊天设置可关闭（99A）。
- 当前聊天生成时禁用历史编辑；完成或手动停止后才能编辑（81B）。
- 报错时保留已收到的半截回复，标明未完成并允许重试（82A）；重试保留失败内容为旧版本，新回答为新版本（83A）。
- 新聊天使用默认模型、最高思考、空系统提示词，其他参数采用默认值，不继承上个聊天的手动覆盖（121A）。
- 历史请求只保存模型、参数、用量等，不额外保留完整请求正文快照（118A）。

### 5.2 消息树

- 存储完整消息树，显示当前选中的路线，不把分支扁平化丢失。
- 编辑历史用户提问：保留旧分支，新提问从相同父节点形成新路线，用户可切换版本；前端交互借鉴最新版 OpenWebUI。
- 重新生成 AI 回答：保留旧回答作为版本，可切换。
- 手动编辑 AI 回答：直接覆盖该回答，不新增修改前版本（5B）。保留后续既有回答；后续新请求使用修改后的内容。
- Fork：用户消息和 AI 回答处均提供入口（112A）；从开头到选中消息，复制当前路线为独立新会话，原会话不变；新会话放在原分组并立即打开（42A）。复制模型、参数、系统提示词副本，不复制输入草稿（113A）。
- Fork 标题在原始基础标题后使用“分支A、分支B……”递增后缀；对已有分支再 Fork 时替换/识别末尾分支后缀，不叠加“分支分支”。具体后缀匹配和防冲突由实现合理处理，用户已允许自行判断（84A 补充）。不为 Fork 自动调用标题模型。
- 可单独删除消息及其后续子分支，操作前显示影响范围（66A）；确认后永久删除，不增加消息级回收站（126A）。会话级回收站仍保留。
- 消息可从上下文排除但保留正文，并显示淡色标记，可一键重新加入（E8、67A）；排除对本会话所有引用该消息的分支生效（116A）。
- 可预览下一次请求会携带的消息/上下文（31A）。
- 消息旁有版本箭头和计数，同时增加可视化树状分支总览，能够查看并切换路线（111B）。手机可用箭头，点击版本数打开版本列表（129A）。

### 5.3 显示与输入

- 基础 Markdown：标题、列表、加粗、链接、表格、普通代码块。不进行代码语法高亮/数学解析。
- 复制整条消息、单独复制代码块。
- 显示上游实际提供的独立思考内容；生成时展开，完成后自动折叠（23A）。不要求模型泄露未提供的思考内容。
- 思考内容保存和展示，但后续请求只发送历史正文，不发送历史思考字段（115A）。
- 最新一条 AI 回复直接显示模型、Token、耗时等；之前的回复在电脑悬停或手机点击时显示详情（22B 的用户补充）。用量未返回时不得伪造实际用量。
- 统计细项包含输入、输出、缓存、思考 Token 和耗时，有实际数据才显示（119A）；本地估算另行标注。
- 时间平时隐藏，悬停或消息菜单查看（12A）。
- 超长用户消息和 AI 回复均可折叠，设置中可关闭（13B 加用户补充）。
- 自动滚动；用户阅读旧消息时不强行拉回底部。
- 电脑默认 Enter 发送、Shift+Enter 换行，设置可改；手机回车换行，点击发送。
- 复制默认采用原始 Markdown，同时在菜单提供纯文字复制（96AC）。
- 不增加新聊天/聚焦输入/打开设置等额外快捷键，仅保留已确认的发送/换行相关快捷键（97B）。
- 输入框可展开为大编辑区域，适合长文字（117A）。不增加长聊天消息目录，保留正常滚动与回到底部（120A）。

## 六、系统提示词和上下文

- 无全局默认系统提示词；每个聊天自己设置（24B）。原第 25 题“修改全局系统提示词”不适用。
- 可以保存多个有名字的系统提示词模板，手动选择，新聊天默认不添加系统提示词。此前“系统角色＋输入文字两类模板”建议未被选择，不能自动扩大范围。
- 模板可多选（55B），按选择顺序排列并可调整顺序（76A）；每个模板为独立可编辑卡片（77B），按顺序组成实际系统提示词。
- 使用的系统提示词保存为当前聊天内容副本；之后修改模板不会自动改变旧聊天，重新选择才更新（56A）。
- 重新选择模板时支持替换和追加两种模式，在右侧对话设置切换（78），默认替换（130A）。模板仅保存普通文字，不自动替换日期/时间等占位内容（79A）。
- 默认发送当前分支全部文字上下文，可手动限制最近若干轮；保留完整历史，不自动总结。
- Codex 样式圆环展示上下文使用情况，计入当前分支、系统提示词和输入草稿；随输入/模型/分支/排除项变化更新估算（53A）。
- 模型容量初值 1,048,576 Token，可在模型列表修改。
- 超过所设容量只提示，仍允许发送，不自动删除旧消息（54A）。手动选择的轮数限制仍生效。
- 明确区分本地 Token 估算和上游实际 usage。

## 七、标题、分组、归档和回收站

- 新建、重命名、删除、置顶、归档、导出聊天。
- 首轮回答完成后调用模型生成标题，之后可手动重新生成（7A）；手动改过标题不再自动覆盖。
- 设置中可自定义标题生成提示词，选择服务商和模型；未单独配置时使用当前聊天模型（36A）。
- 标题生成失败则尝试默认聊天模型（37B）；具体重试应有界，不能无限循环。
- 手动点击重新生成标题，完成后直接替换，不增加确认预览步骤（38B）。
- 手动重生标题的材料范围可选“当前分支问答”或“仅首轮问答”，切换项放在右侧（80），默认当前分支（131A）。
- 左侧聊天按最近活动排序；置顶在前。不按今天/昨天等时间分类。
- 分组外观类似 ChatGPT 项目，但仅用于将聊天放在一起；单层，无跨对话上下文、共享提示词、资料或项目记忆。
- 支持拖拽或菜单移动聊天。
- 在分组内新建聊天自动放入该分组（122A）。
- 分组按最近活动自动排序（90B）；组内置顶在本组内，未分组的置顶在主列表内，不额外集中所有分组的置顶项（89A）。
- 删除分组只移除分组，聊天回主列表（41A）。
- 回收站不自动清理，手动永久删除前一直保留（8D）。
- 左侧提供归档入口（88A）。归档保留原分组关系，取消归档回原位置（91A）；从回收站恢复时若原分组已删除，恢复到主列表，不自动重建分组（92A）。
- 支持多选聊天，批量移动、归档、删除和导出（69A）。
- 移动、归档、移入回收站后不提供即时“撤销”提示条，使用对应管理入口恢复（98B）。单条消息/子分支按 126A 确认后永久删除。

## 八、OpenWebUI 导入导出与验收

### 8.1 已确认的兼容范围

- 以实现时最新版 OpenWebUI 稳定版为依据，固定具体版本/提交后核实结构。
- 核心目标：OpenWebUI 导出 → 本应用导入 → 本应用再导出 → OpenWebUI 可重新导入。
- 保存完整消息树、父子关系、全部文字分支、当前路线、模型、时间、标题及与文本聊天有关的原始字段/元数据，不只保存当前可见消息数组。
- 对不在本产品中实现的字段，优先保留为兼容数据而不执行对应功能；用户明确要求清除的附件及其引用除外。
- 历史附件/文件内容与引用按用户要求清除，不迁移附件存储。正文图片 Markdown 可保留原始文本或链接但不加载图片（87A），不把外部图片自动转成远程加载请求。
- 模型匹配失败采用默认模型续聊，历史模型元数据保留。
- 每次导入新增聊天，不去重，不覆盖已有聊天（3A）。
- 导入前预览会话数、分支数、将清除的附件数量，再点击导入（68A）。
- 一批中部分聊天无效时，导入有效聊天，列出失败项和原因，不因一条无效取消整批（86A）。
- Markdown 导出仅当前选中路线；兼容 JSON 导出完整消息树（43A）。
- 不把额外 ChatGPT/其他平台格式转换作为已确认功能；是否需要由后续明确授权决定。

### 8.2 实现时应验证

1. 多条用户编辑分支、多个重新生成回答版本可双向往返。
2. 当前分支位置、消息时间、正文、思考内容和能保留的元数据不因转换丢失。
3. 按用户要求清除附件；保留相邻文字，不把整条用户提问误删。
4. 重复导入产生独立新会话，修改互不影响。
5. 导入后的 Fork、编辑、切换、重新生成后，导出仍能被选定 OpenWebUI 版本读取。
6. 明确区分聊天兼容备份、回收站导出、本应用设置备份。
