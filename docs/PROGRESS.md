- 用户编辑新分支、AI 编辑原位覆盖、重新生成/重试/续写版本、祖先路线 Fork、排除上下文、子树删除、版本箭头、直接版本列表与树状路线选择。
- Workflow 等待每任务独立 SQLite Durable Object 完成唯一上游调用。HTTP 返回 202；刷新/关闭页面只读取原任务。部分输出约每 2 秒落入 DO，最终回答与 job 状态原子写入 D1。
- 首次回答自动标题、手动重生标题、独立模型/提示词、首轮/当前分支材料范围。独立 Workflow + DO 调用；最多尝试两个不同模型，默认模型后备只一次；失败不回滚正文，手动改名可使旧任务失效。
- 设置备份与聊天 JSON 分开。默认不含 Key；主动包含时标注普通 JSON 并再次验证密码；恢复先预览、再明确选择合并/替换。全部配置校验后原子写入，不迁移登录凭证；无 Key 的备份仅保留相同服务商 ID 且地址未变的已有 Key。
- 系统模板可多选，按选择顺序复制到当前聊天，可调整卡片顺序和替换/追加；编辑副本不修改模板。实际 usage 仅显示上游返回的输入/输出/缓存/思考/总计，历史回复悬停或消息菜单查看。
- 桌面侧栏可拖动/键盘调整并按设备记忆；手机长按消息菜单及直接版本列表。模态框焦点限制、Escape、关闭后恢复焦点；当前可见聊天完成后清除未读点。

## 数据迁移与边界

- `0002.sql` 增加标题任务/唯一约束与分组归属触发器；`0003.sql` 增加独立草稿及不可变分块。`dev:init` 通过 `d1_migrations` 逐个原子应用未执行迁移，兼容之前本地只有 `0001.sql` 的状态。
- 草稿更新不读取/重写完整消息树。普通聊天保存保留独立草稿，发送消息时才在同一事务内清空草稿；旧版文档内草稿在保存时安全迁移，不覆盖更新过的独立草稿。
- 每块最多 524288 个 UTF-16 单位，避免拆开代理对且 UTF-8 单值低于 D1 2 MB。文档最多 40 块、HTTP JSON 请求最多 10 MiB；批量聊天导入界面逐项提交、显示成功与失败，后端单次超限在写入前拒绝；每个原子批处理最多 40 条 SQL（为同次调用的认证/配置/任务查询预留额度）。超大设置备份会在写入前拒绝，需分批合并；大型替换恢复还需改进。
- 聊天历史仍为不可变分块快照；除草稿外，改动仍重写当前历史。暂不声称接近 1,048,576 Token 预算的所有输入都能在免费 HTTP CPU/内存/查询额度内完成。预算不是上游能力或已验证上限。
